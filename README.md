# 太一数科 · 优品购电商数仓工作台

使用 Vue 3、TypeScript、Vite、Vue Router、Pinia 与 Apache ECharts 构建的电商分析前端。默认在浏览器内使用可复现的交易数据，经营总览、数仓明细、画像与 Text2SQL 可按同一批订单对账。数仓和 Text2SQL 服务均通过独立的 HTTP 接口接入。

## 本地启动

准备 Node.js 22.12 或更高版本。在解压出的项目目录或克隆后的仓库根目录运行以下命令。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。首次进入时使用 Mock 管理员；左下角用户菜单可以切换联调角色。右上角可查阅指标口径、切换浅色或暗黑模式。请使用本地开发服务器或 HTTPS 站点访问，以便浏览器加载模块与 SQL 引擎的 WASM 资源。

| 命令                                    | 用途                                                      |
| --------------------------------------- | --------------------------------------------------------- |
| `npm run typecheck`                     | 检查 TypeScript 与 Vue 模板类型                           |
| `npm run lint` / `npm run format:check` | 检查 ESLint 规则与 Prettier 格式                          |
| `npm run format`                        | 按仓库约定格式化文件                                      |
| `npm test`                              | 执行 Vitest 回归测试，包括交易去重、跨页面对账和 SQL 查询 |
| `npm run build`                         | 先检查类型，再生成生产静态文件到 `dist/`                  |
| `npm run preview`                       | 本地预览上一步的生产构建                                  |

组件集成测试在 jsdom 中挂载实际的工作台、路由和状态管理，覆盖筛选到订单下钻、切换角色后的访问拦截，以及自然语言生成 SQL 后确认执行并回显结果。图表像素渲染与原生弹窗展示需通过浏览器验收。

## 页面与操作

| 页面            | 地址            | 可复核的操作                                                                                                     |
| --------------- | --------------- | ---------------------------------------------------------------------------------------------------------------- |
| 经营总览        | `/#/`           | 组合日期、渠道、品类、地区筛选；查看四项核心指标；切换折线或柱状趋势；从品类占比、日期明细下钻；导出所选区间日报 |
| 维度分析        | `/#/dimensions` | 切换分析维度和排序指标，从品类下钻到商品，按权限打开订单；用雷达图比较两个维度项                                 |
| 用户画像        | `/#/portrait`   | 选择统计日和 30/60/90 天窗口，按单次或多次下单、常用地域筛人，查看用户标签及来源，导出当前页                     |
| 分层数据探查    | `/#/warehouse`  | 逐层选择 ODS/DWD/DWS/ADS 表，查看字段、粒度、上游与分页记录                                                      |
| 变更追踪        | `/#/changes`    | 按订单检查 CDC 新增、更新、删除事件，对照拉链版本与指定日期快照                                                  |
| 明细查询        | `/#/details`    | 按日期和业务维度查询订单，排序、翻页、导出当前页；打开订单查看全部商品行                                         |
| Text2SQL 工作台 | `/#/textsql`    | 发送问题、编辑 SQL、校验、启用执行并检查结果；通过历史记录或收藏恢复查询                                         |

**一次端到端联调**可从默认周 2026-11-14 至 2026-11-20 入手。该周交易总额为 690,406.80 元，去重订单 2,096 笔，去重下单人数 1,645 人，客单价 419.70 元。在「分层数据探查」选择 ADS 的当日交易综合统计表，核对各日金额。在「Text2SQL 工作台」发送“最近 7 天每天的 GMV 和订单量是多少？”，校验并执行，最后一天应为 79,236.08 元、231 单。交易总额按下单口径统计，包含后来取消的订单；跨日汇总人数时须对会员重新去重。

## Mock 数据与权限

数据范围为 2026-07-24 至 2026-11-20，共 120 个业务日，固定种子生成 31,133 笔订单、42,041 条商品行。字典包含 5 个品类、20 个商品、4 个渠道与 6 个地区。日期、字典和种子位于 `src/mocks/data/analyticsCatalog.json`，生成逻辑位于 `analyticsFacts.ts`。金额以整数分累加，在公开接口中转为元。各页面按当前条件重新聚合，刷新操作会重取同一份分区数据。

结构化测试数据提供默认区间、联合筛选、空集、分页和一笔三品类订单的输入与期望。用订单 `TY2026112000029` 可核对 3 行、4 件、764.16 元。变更追踪另有 `CDC-REMOVED-001`，该订单在 2026-11-18 有效，2026-11-19 的删除事件关闭其最后一个版本。 [结构化联调样例](./src/mocks/data/analyticsScenarios.json)

| 联调角色         | 允许访问                                                         |
| ---------------- | ---------------------------------------------------------------- |
| 管理员 `admin`   | 全部页面与只读 SQL 执行                                          |
| 分析师 `analyst` | 经营、维度、画像、分层探查、订单明细与 Text2SQL，含只读 SQL 执行 |
| 访客 `viewer`    | 经营总览、维度分析                                               |

角色决定导航显示与直接访问路由时的检查结果。HTTP 模式从 `/session/me` 读取身份和权限，后端据登录会话逐请求授权。Mock 将主题、所选角色以及按用户隔离的 SQL 历史和收藏保存在当前浏览器。Text2SQL 在 Mock 模式下用规则模板生成查询，使用本地 SQLite 解析和执行；真实自然语言模型与数仓连接由后端提供。

## 切换环境与部署

开发、生产配置分别读取 `.env.development`、`.env.production`，默认均为 `mock://warehouse`。在开发机创建 `.env.development.local`，或在构建环境设置同名变量以连接真实服务。以下示例将两个服务挂在同一域名下。若 SQL 与数仓使用同一网关，可省略第二行。

```dotenv
VITE_API_BASE_URL=/api/v1
VITE_TEXT2SQL_BASE_URL=/query-api/v1
```

保存后重启开发服务器。生产环境可通过 `.env.production.local` 或 CI 环境变量指定地址，再执行 `npm ci` 与 `npm run build`。将整个 `dist/` 部署到域名根路径，保留资源目录与 WASM 文件，静态服务为 WASM 提供 `application/wasm`。页面使用 hash 路由，服务器处理应用入口和静态资源。Vite 会将 `VITE_*` 写入浏览器资源，这些变量仅存公开的服务地址。

业务网关实现下列文档约定后，修改地址、重新构建即可让现有页面使用真实返回。浏览器携带会话 Cookie，生产登录与访问凭据由网关或组织的身份服务管理。推荐把接口挂在应用同源路径，跨域接入要求后端显式允许前端来源、请求头与凭据。

- 各端点、字段、分页和 HTTP 样例见 [API 契约](./docs/api.md)。
- 五份 PDF 的章节索引、六张交易表、客单价、拉链区间和画像标签见 [数仓字段映射](./docs/warehouse-mapping.md)。
- 自然语言生成、查询校验、执行与收藏的独立接入约定见 [Text2SQL 接入说明](./docs/text2sql.md)。
