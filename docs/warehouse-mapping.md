| ADS `ads.ads_order_stats`             | 每行一个 `calc_dt`，原文 DDL 为非分区表                                                                  | 输出 `order_total_amount`、`sku_cnt`、`order_user_cnt`、`order_cnt`，作为每日综合统计基线。                                       |

页面时段和维度交叉筛选需要更细的事实键。服务层可通过订单商品事实关联订单头的渠道、地域，再关联 SKU 对应业务日期的品类。实际订单同时命中多个品类时，各品类 GMV 按命中的商品行分配，单笔订单可以出现在多个品类的订单计数中。按品类或 SKU 下钻的订单列表展示匹配行的小计与件数；打开某一订单的详情可以看到整单所有商品。

## 指标对账

| 接口字段 | 显示指标           | 在当前筛选范围内的计算                                         |
| -------- | ------------------ | -------------------------------------------------------------- |
| `gmv`    | 商品交易总额（元） | 合计匹配订单行的最终金额。与日报的 `order_total_amount` 对照。 |
| `orders` | 订单数（笔）       | 按 `order_sn` 去重；一笔订单的多条商品明细只计一次。           |
| `buyers` | 下单人数（人）     | 按 `member_id` 去重；跨日、跨 SKU 均需重算去重。               |
| `pieces` | 下单件数（件）     | 合计匹配订单行的 `sku_num`。                                   |
| `basket` | 客单价（元/人）    | 总 GMV ÷ 下单人数。若另行统计笔单价，分母应为去重订单数。      |

交易指标按下单发生日归属。Mock 将取消单也计入下单事实，金额先按整数分累加，接口以元返回。环比向前移动一个等长时段并沿用当前维度过滤；基期覆盖不足或分母为零时，变化率返回 `null`。支付金额、退款金额、履约收入各有自己的事件时间和状态条件，新增这些指标时应另外建立事实口径。对照《主题计算》§10.3.1 的示范 SQL 时，尤其需区分订单创建、版本生效和支付三个日期；订单更新产生新版本后，下单日期仍取原始创建日期。

按周、按月分析时，区间总人数应从保留会员键的明细或可合并的精确去重集合计算。将每日 ADS 的 `order_user_cnt` 相加会重复计算连续多日下单的同一会员。客单价同样应从区间总额和区间去重人数重算。

## CDC 与历史快照

CDC 记录一条变更事件，支持查看变更前后值。源端插入只有后值，更新有前后值，删除只有前值。订单拉链按日保留同一订单当天最后一个状态，能回答“该订单在某个业务日结束时是什么状态”。若一天内发生多次变更，需查看 CDC 事件序列才能还原先后顺序。

《功能设计》§4.5.1 以新版本生效日关闭上一版本，最新版本的 `zip_end_dt` 为 `9999-12-31`。查询业务日 D 时采用 `zip_start_dt <= D AND D < zip_end_dt`。因此在切换日只选中新版本。Mock 另设源端删除样例验证闭链，删除日之后的日末快照排除该订单。真实部署需由 CDC 消费服务处理同键顺序、重复事件和删除；离线 DataX 增量抽取是否能识别删除，取决于源端提供的删除标记或变更日志。

## 画像窗口

《用户画像》§4.3 的 `ads.ads_profile_order_tag` 按 `dt` 组织会员画像，包含 `month1_order_cnt`、`month1_order_amt` 和 60/90 日对应字段。文档中的首末下单时间、累计消费与近 30 日指标具有不同的历史范围。前端窗口内的首末下单日、最大或最小单额仅覆盖用户选择的统计期。标签纵表保留统计日、起止日、会员标识、标签名和标签值。Mock 按窗口将一笔订单的会员归为单次下单，将至少两笔的会员归为多次下单；常用地域按订单数统计，最常购买一级品类按订单商品行数统计。两项并列时均以 ID 排序取首项。

## 真实接口接入与核验

1. 根据本项目的 TypeScript 请求和响应类型提供 HTTP 网关，服务端连接数仓或 OLAP 引擎。元数据中给出表名、字段名、数据类型和粒度。Mock 只提供页面使用的字段投影；原始 DDL 的全部列、优惠券任务、维表作业与 ETL 部署分别见相应 PDF。
2. 固定业务时区、下单归属日期、人民币单位及日分区完成时间。网关统一映射订单来源、品类和地域 ID，原始仓库表名和界面中文名称可以分别演进。
3. 选取同一天含多个 SKU 的订单，以及跨天复购的会员，对照订单头、商品行和日报验证金额、件数、去重计数和客单价。用“无历史、首次下单、订单更新日、物理删除日”样例对账环比、拉链和 CDC。
4. 真实服务使用会话身份实施页面、行列和执行权限，应用稳定排序键后再分页。Text2SQL 的执行与结果边界见独立接入说明。 [Text2SQL 接入文档](./text2sql.md)
